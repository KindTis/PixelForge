# AI 픽셀 도구 편집 설계

작성일: 2026-08-12
상태: 사용자 승인

## 목표

사용자가 자연어로 편집을 지시하면 Codex가 새 이미지를 생성하지 않고 PixelForge의 기존 픽셀 편집 도구를 사용해 현재 선택된 셀만 편집한다.

예시:

- "배경을 빨간색으로 칠해줘" → 채우기 도구 동작
- "좀비의 팔에 핏자국을 그려줘" → 연필 도구 동작

성공한 AI 동작은 사용자가 직접 도구를 조작했을 때와 동일한 편집 명령과 실행 취소 규칙을 사용한다.

## 범위

### 포함

- 요청 시점에 선택된 프레임과 활성 레이어가 이루는 셀 하나만 편집
- 현재 제공되는 도구 14개 모두 지원
  - 연필, 지우개, 직선, 곡선, 사각형, 타원, 다각형
  - 채우기, 그라디언트, 스프레이, 스포이드
  - 사각 선택, 올가미, 마술봉
- 합성 프레임과 활성 셀을 함께 사용해 대상 위치 판단
- AI가 반환한 도구 동작을 기존 `ToolController`와 `History`로 실행
- 픽셀을 변경하는 각 도구 동작을 개별 실행 취소 단계로 기록
- 기존 이미지 생성과 선택 프레임 재생성 기능 유지

### 제외

- AI 이미지 생성으로 편집 결과 제작
- 브라우저 포인터나 화면 좌표를 직접 자동 조작
- 현재 도구 자체의 동작 변경 또는 기능 확장
- 여러 셀, 여러 프레임 또는 여러 레이어를 한 요청에서 편집
- 새 AI 공급자, API 키 또는 외부 의존성 추가

## 사용자 경험

기존 `CODEX FORGE` 패널의 프롬프트를 공유하는 `현재 셀 편집` 버튼을 추가한다. 버튼을 누른 시점의 프레임, 레이어, 셀을 작업 대상으로 고정한다.

AI가 편집을 해석하는 동안에는 다음 동작을 막는다.

- 캔버스 편집
- 프레임 전환
- 활성 레이어 전환
- 대상 셀을 변경할 수 있는 타임라인·레이어 조작

완료하면 적용된 동작 수와 AI 요약을 표시한다. AI가 대상을 확실히 찾지 못하면 동작을 만들지 않고 이유만 표시한다. 기존 이미지 생성, 선택 프레임 재생성, 생성 이력은 변경하지 않는다.

성공한 작업의 마지막 도구, 전경색·배경색, 브러시 설정과 선택 영역은 사용자가 직접 작업한 경우처럼 편집 화면에 유지한다.

## 구조

기존 책임 경계를 유지한다.

- `App`: 요청 시작, 상태 폴링, 편집 결과 전달, 진행·오류 표시
- `EditorWorkspace`: 현재 대상과 도구 설정 제공, 반환된 동작 실행, 편집 이력과 화면 상태 반영
- `ToolController`: AI 동작을 사용자 포인터 제스처와 같은 편집 명령으로 변환
- `History`: 픽셀 변경 동작별 실행 취소·다시 실행 보존
- 서버: 저장된 프로젝트에서 참조 이미지를 만들고 Codex 작업을 관리하며 구조화 결과를 반환
- `CodexBridge`: 이미지 생성 스킬 없이 로컬 이미지 입력과 JSON 출력 스키마로 편집 동작 요청

서버는 AI 편집 결과로 프로젝트 픽셀을 직접 변경하거나 저장하지 않는다. 편집기만 기존 명령 경로를 통해 프로젝트를 변경한다.

## AI 입력

Codex에는 다음 정보를 전달한다.

1. 사용자의 자연어 지시
2. 문서 너비와 높이
3. 활성 셀의 프레임·레이어 이름과 식별 정보
4. 현재 도구 설정
5. 격자나 UI 표시가 없는 현재 프레임의 합성 PNG
6. 투명 배경 위에 문서 좌표로 정렬한 활성 셀 PNG
7. 사용 가능한 도구와 구조화 출력 계약

합성 프레임은 팔이나 배경 같은 의미적 위치를 찾는 참조다. 활성 셀 이미지는 실제로 읽고 변경할 수 있는 픽셀을 구분하는 참조다. 두 이미지는 문서 좌상단을 `(0, 0)`으로 사용하는 동일한 좌표계를 갖는다.

셀에 오프셋이 있으면 활성 셀 PNG를 문서 크기의 투명 캔버스에 배치한다. AI는 문서 좌표만 반환하고, 실행기가 셀 오프셋을 반영해 셀 내부 좌표로 변환한다.

화면 캡처는 입력으로 사용하지 않는다. 확대, 이동, 격자, 선택선, 어니언 스킨, 타일 미리보기가 실제 픽셀과 좌표 판단을 방해할 수 있기 때문이다.

## 구조화 출력

Codex의 최종 응답은 JSON 출력 스키마로 제한한다.

```ts
type AiEditResult = {
  summary: string;
  actions: AiToolAction[];
};

type AiToolAction = {
  tool: EditorTool;
  points: Array<{ x: number; y: number }>;
  color?: RGBA;
  secondaryColor?: RGBA;
  brushSize?: number;
  brushShape?: "square" | "circle";
  filled?: boolean;
  mirrorX?: boolean;
  mirrorY?: boolean;
};
```

`tool`은 현재 `EditorTool` 열거형에 있는 값만 허용한다. `points`에는 도구 제스처를 구성하는 문서 픽셀 좌표를 순서대로 담는다.

- 첫 좌표 → `pointerDown`
- 중간 좌표 → 차례대로 `pointerMove`
- 마지막 좌표 → `pointerUp`
- 좌표가 하나뿐인 클릭 도구 → 같은 좌표로 `pointerDown`과 `pointerUp`

도구 설정이 생략되면 직전 AI 동작의 상태를 이어받으며, 첫 동작은 요청 당시 편집기 설정에서 시작한다.

## 도구 실행 의미

모든 도구는 기존 `ToolController`의 의미를 그대로 사용한다. AI 전용 래스터 알고리즘을 만들지 않는다.

- 연필·지우개·스프레이는 전체 좌표 경로를 사용한다.
- 직선·곡선·사각형·타원·다각형·그라디언트·사각 선택은 시작점과 끝점을 사용한다.
- 채우기·스포이드·마술봉은 클릭 좌표를 사용한다.
- 올가미는 닫힌 선택 경로를 사용한다.
- 스포이드 결과는 이후 AI 동작의 전경색이 된다.
- 사각 선택·올가미·마술봉 결과는 이후 AI 동작을 제한하고 완료 후 화면에 남는다.
- 선택 도구와 스포이드는 현재 동작처럼 문서 편집 이력에 추가하지 않는다.
- 픽셀을 변경한 각 제스처는 별개의 `History` 항목이 된다.
- 픽셀 변경이 없는 제스처는 이력을 만들지 않는다.
- 인덱스 색상 모드는 기존 팔레트 제한을 그대로 적용한다.

다각형과 곡선을 포함한 각 도구의 기하 규칙은 현재 사용자가 같은 포인터 입력을 보냈을 때의 결과와 동일하다.

## 요청 및 적용 흐름

1. `App`이 현재 프로젝트의 미저장 변경을 저장한다.
2. 편집기가 프레임 ID, 레이어 ID, 셀 ID, 현재 도구 설정을 요청에 담는다.
3. 서버가 프로젝트 잠금을 획득하고 저장된 대상이 요청과 일치하며 레이어가 잠기지 않았는지 확인한다.
4. 서버가 합성 프레임과 문서 좌표로 정렬된 활성 셀 PNG를 임시 작업 경로에 만든다.
5. `CodexBridge`가 텍스트, 두 로컬 이미지와 JSON 출력 스키마를 새 편집 작업으로 전달한다. `imagegen` 스킬은 조회하거나 전달하지 않는다.
6. 서버가 Codex의 최종 응답을 수집하고 JSON으로 해석한 뒤 런타임 검증한다.
7. 클라이언트가 완료된 작업을 받아 요청 당시 대상과 현재 대상이 일치하는지 다시 확인한다.
8. `EditorWorkspace`가 별도의 임시 `History`에서 동작을 순서대로 실행한다.
9. 모든 동작이 성공하면 임시 `History`와 최종 문서를 현재 편집기에 반영한다.
10. 기존 자동 저장이 변경된 프로젝트를 저장한다.

임시 `History`를 사용하므로 적용 도중 예상하지 못한 실패가 발생해도 부분 결과는 화면에 반영되지 않는다. 성공 후에는 내부에 쌓인 각 변경 동작을 `Ctrl+Z`로 한 단계씩 취소할 수 있다.

## 검증과 오류 처리

AI 응답은 신뢰 경계의 입력으로 취급한다. 실행 전에 전체 동작 배열을 검증한다.

- `tool`이 현재 지원 목록에 있는지 확인
- 각 동작에 좌표가 하나 이상 있는지 확인
- 모든 좌표가 정수이며 문서 범위 안인지 확인
- RGBA 각 채널이 0~255 정수인지 확인
- 브러시 크기가 현재 편집기의 1~32 범위인지 확인
- 브러시 모양과 불리언 설정 값 확인
- 동작 수가 128개 이하인지 확인
- 전체 좌표 수가 `max(256, min(문서 너비 × 문서 높이 × 4, 16384))` 이하인지 확인
- 요청한 프레임·레이어·셀 관계가 유지되는지 확인
- 레이어가 잠기지 않았는지 확인

다음 상황에서는 프로젝트를 변경하지 않고 한국어 오류를 표시한다.

- Codex 연결 또는 작업 실패
- 응답이 출력 스키마나 런타임 검증을 통과하지 못함
- 대상 프레임·레이어·셀이 삭제되거나 변경됨
- 대상 레이어가 잠김
- 실행 도중 예기치 않은 도구 오류 발생

`actions`가 비어 있는 유효한 응답은 오류가 아니다. `summary`를 사용자에게 표시하고 셀은 그대로 둔다.

## 작업 상태

기존 비동기 생성 작업의 시작, 상태 폴링, 취소, 메시지 수집 흐름을 재사용한다. 작업 종류를 이미지 생성과 셀 편집으로 구분하고, 셀 편집 완료 응답에는 프로젝트 이미지 대신 검증된 동작 배열과 대상 식별 정보를 담는다.

사용자가 편집 작업을 취소하면 Codex 실행을 중단하고 프로젝트 잠금을 해제한다. 임시 참조 이미지는 작업 종료 후 제거한다.

## 테스트

GUI를 띄우지 않는 단위·서버 테스트를 우선한다.

1. 구조화 출력 검증
   - 14개 도구 이름 허용
   - 잘못된 도구, 좌표, 색상, 브러시 설정 거부
   - 빈 동작 결과 허용
2. 도구 실행
   - 각 도구가 일반 포인터 제스처와 같은 `ToolController` 결과 생성
   - `선택 → 스포이드 → 그리기 또는 채우기` 상태 전달
   - 셀 오프셋 좌표 변환
3. 편집 이력
   - 픽셀 변경 제스처마다 실행 취소 항목 하나 생성
   - 여러 AI 동작을 역순으로 한 단계씩 실행 취소·다시 실행
   - 선택과 스포이드가 문서 이력을 만들지 않음
4. 격리
   - 활성 셀만 변경
   - 다른 프레임과 레이어의 셀 및 이미지 보존
   - 연결 셀은 기존 명령 규칙에 따라 편집 시 분리
5. Codex 연결
   - 합성 프레임과 활성 셀을 `localImage`로 전달
   - JSON 출력 스키마 전달
   - `imagegen` 스킬을 조회하거나 입력에 포함하지 않음
6. 서버 흐름
   - 대상 고정, 프로젝트 잠금, 완료·취소·실패 처리
   - 잘못된 응답과 대상 불일치 시 프로젝트 보존
   - 기존 이미지 생성 작업 회귀 방지
7. 최종 검증
   - `npm test`
   - `npm run build`
   - 코드 변경 후 `graphify update .`

별도의 브라우저 E2E 도구와 새 테스트 프레임워크는 추가하지 않는다.

## 완료 기준

- 자연어 지시가 새 이미지 생성 없이 기존 도구 동작으로 변환된다.
- 14개 도구가 현재 편집기와 동일한 의미로 실행된다.
- AI가 본 대상과 실제 변경된 대상이 동일하다.
- 현재 선택된 셀 이외의 픽셀 데이터는 변경되지 않는다.
- 각 픽셀 변경 동작을 한 단계씩 실행 취소할 수 있다.
- 실패하거나 빈 동작을 반환할 때 프로젝트 픽셀이 유지된다.
- 기존 이미지 생성·프레임 재생성 기능과 전체 테스트·빌드가 정상 동작한다.
