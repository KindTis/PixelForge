# AI 셀 편집 독립 판정 반복 설계

작성일: 2026-08-15
상태: 사용자 승인

## 문서 성격과 상속 범위

이 문서는 [AI 픽셀 도구 편집 설계](./2026-08-12-ai-pixel-tool-editing-design.md)에 독립 판정과 조건부 재편집을 추가한다. 기존 현재 셀 편집의 대상 고정, 도구 동작, 실행 취소, 프로젝트 잠금과 입력 검증은 이 문서에서 변경한 부분을 제외하고 그대로 유지한다.

## 문제와 목표

편집 에이전트가 유효한 도구 동작을 반환하더라도 결과가 사용자 요청, 캐릭터 자세와 픽셀 아트 스타일을 충족한다는 보장은 없다. 편집 에이전트가 자신의 결과를 직접 평가하면 같은 판단 오류를 반복할 수 있다.

따라서 현재 셀의 후보 편집 결과를 별도의 판정 에이전트가 검사하고, 불합격일 때만 판정 피드백을 사용해 재편집한다. 합격한 결과만 현재 셀에 적용하며 모든 후보 이미지와 판정을 로컬 로그로 남긴다.

## 확정된 제품 규칙

- 적용 범위는 `현재 셀 편집`뿐이다.
- 편집과 판정은 동일한 `gpt-5.6-sol` 모델과 동일한 추론 설정을 사용한다.
- 편집과 판정은 서로 다른 에이전트 역할과 서로 분리된 새 스레드에서 실행한다.
- 각 편집 시도와 각 판정은 이전 스레드 기록을 상속하지 않는다.
- 최초 편집은 1회 수행한다.
- 판정이 불합격일 때만 재편집하며 재편집은 최대 5회다. 따라서 편집과 판정은 각각 최대 6회다.
- 판정이 합격하면 남은 횟수와 관계없이 즉시 종료한다.
- 재편집은 직전 불합격 후보를 수정하며 원본도 함께 참고한다.
- 6번째 후보까지 불합격이면 전체 작업을 실패 처리하고 원본 셀을 유지한다.
- 판정에 사용한 이미지, 판정 JSON과 작업 요약은 프로젝트 안에 영구 보존한다.

동일 모델을 사용하므로 모델 계열 자체의 편향은 공유할 수 있다. 이 설계에서 보장하는 독립성은 역할, 시스템 지시와 대화 문맥의 격리다.

## 범위 제외

- 선택 프레임 재생성과 전체 시트 생성
- 다른 모델 또는 외부 AI 공급자 추가
- 사용자가 직접 재시도 횟수나 판정 기준을 설정하는 UI
- 시도별 결과를 보여주는 앱 내 썸네일 갤러리
- 로그 자동 만료, 용량 제한과 정리 UI
- 실제 모델을 반복 호출하는 자동화 테스트
- 의류나 치마 같은 특정 편집 종류에만 적용되는 프롬프트 규칙

## 검토한 구조

### 선택: 서버 주도 반복 작업

서버의 단일 셀 편집 작업이 편집, 후보 적용, 판정, 재편집, 로그와 종료를 관리한다. 클라이언트는 작업을 시작하고 상태를 폴링한 뒤 합격 결과만 적용한다.

이 구조는 반복 횟수, 취소, 오류, 프로젝트 잠금과 로그를 한곳에 모으며 판정 에이전트 분리를 서버에서 강제한다.

### 제외: 클라이언트 주도 반복 작업

클라이언트가 후보를 임시 적용하고 판정·재편집 요청을 차례로 호출하는 방법은 현재 편집 실행기를 바로 사용할 수 있다. 그러나 새로고침과 화면 이동에 취약하고 작업 상태가 클라이언트와 서버에 분산되므로 제외한다.

## 구조와 책임

### 셀 편집 작업

기존 `CellEditJob`이 다음 상태를 추가로 보유하고 전체 반복을 관리한다.

- 현재 단계: `editing` 또는 `judging`
- 현재 시도: 1~6
- 최대 시도: 6
- 요청 시점의 원본 문서와 편집기 설정
- 현재 후보 문서와 편집기 설정
- 합격 후보를 재현할 시도별 동작 묶음과 난수 시드
- 마지막 판정 요약
- 프로젝트 기준 로그 상대 경로
- 현재 실행 중인 편집 또는 판정 실행 식별자

외부 작업 상태는 기존 `running`, `finalizing`, `completed`, `failed`, `cancelled`를 유지한다. `phase`, `attempt`, `maxAttempts`, `lastVerdict`, `logPath`만 완료 전 상태 응답에 추가한다.

### 공용 편집 실행기

현재 클라이언트 전용 위치의 순수 도구 실행 로직을 공용 코어의 깊은 모듈로 옮긴다. 서버는 후보 생성에, 클라이언트는 최종 적용에 같은 인터페이스를 사용한다.

실행기는 문서·편집기 설정·대상·검증된 동작 묶음·난수 시드를 받고 다음 값을 반환한다.

- 변경된 문서
- 변경된 편집기 설정
- 실행 취소에 사용할 문서 단계
- 실제 적용된 동작 수

스프레이처럼 난수를 사용하는 도구도 서버 후보와 클라이언트 적용 결과가 같아야 한다. 서버가 시도별 시드를 생성하고 최종 결과에 동작 묶음과 함께 반환한다. 클라이언트는 같은 시드로 각 묶음을 순서대로 재생한다.

### Codex 연결

편집 실행과 판정 실행은 서로 다른 시작 메서드와 출력 스키마를 사용한다. 두 실행 모두 새 스레드를 만들며 읽기 전용 로컬 이미지 입력과 구조화 JSON 출력만 허용한다. 파일 쓰기, 셸과 외부 도구 실행 요청은 자동 거부하고 작업을 기술 오류로 종료한다.

## 데이터 흐름

1. 클라이언트가 현재 프로젝트를 저장하고 셀 편집을 요청한다.
2. 서버가 프로젝트를 잠그고 요청 대상과 저장된 셀이 일치하는지 검증한다.
3. 서버가 원본 문서와 편집기 설정을 복제하고 원본 합성 프레임과 원본 셀 PNG를 로그 폴더에 저장한다.
4. 서버가 새 편집 스레드에 사용자 요청, 원본 합성 프레임, 원본 셀과 현재 후보를 전달한다. 최초 시도에서는 현재 후보가 원본이다.
5. 서버가 구조화된 편집 동작을 검증한 뒤 공용 실행기로 현재 후보 복제본에 적용한다.
6. 서버가 후보 합성 프레임과 후보 셀 PNG를 시도 로그에 저장한다.
7. 서버가 새 판정 스레드에 사용자 요청, 고정 판정 기준, 원본 이미지와 후보 이미지만 전달한다.
8. 합격이면 서버가 시도별 동작 묶음과 시드를 최종 결과로 반환한다.
9. 불합격이고 재편집 횟수가 남았으면 직전 후보, 원본과 최신 판정 피드백을 새 편집 스레드에 전달한다.
10. 6번째 판정도 불합격이면 작업을 실패 처리하고 최종 결과를 반환하지 않는다.
11. 클라이언트는 합격 결과 전체를 격리된 상태에서 재생하고 모두 성공한 경우에만 현재 편집기와 실행 취소 이력에 반영한다.

편집 에이전트에는 이전 판정의 구조화 피드백만 제공한다. 판정 에이전트에는 편집 에이전트의 대화, 추론, 동작 선택 이유와 자기평가를 제공하지 않는다.

## 판정 계약

판정은 점수 임계값이 아니라 필수 기준별 합격 여부로 결정한다. 다음 기준이 모두 통과해야 최종 `pass`다.

1. `request_fulfillment`: 사용자 요청이 실제 결과에 완료되었는가
2. `pose_and_geometry`: 대상의 형태, 위치, 방향, 원근과 가림이 원본 자세에 맞는가
3. `replacement_integrity`: 제거·교체 대상의 불필요한 흔적이나 투명한 빈 공간이 남지 않았는가
4. `preservation`: 신체, 다른 의상, 배경 등 요청하지 않은 영역이 훼손되지 않았는가
5. `pixel_art_consistency`: 해상도, 윤곽, 명암, 팔레트와 투명도가 기존 픽셀 아트에 맞는가

판정 출력은 다음 형태로 제한한다.

```ts
type AiEditVerdict = {
  verdict: "pass" | "fail";
  summary: string;
  criteria: Array<{
    id: "request_fulfillment" | "pose_and_geometry" | "replacement_integrity" | "preservation" | "pixel_art_consistency";
    passed: boolean;
    reason: string;
  }>;
  corrections: Array<{
    criterion: string;
    region: string;
    problem: string;
    requiredChange: string;
  }>;
};
```

`verdict`가 `pass`이려면 모든 기준의 `passed`가 `true`이고 `corrections`가 비어 있어야 한다. 서버는 이 불변식을 다시 검증한다. 불합격 시 `corrections`는 다음 편집 스레드가 바로 실행할 수 있는 구체적인 위치와 수정 요구를 담아야 한다.

## 로그

로그는 현재 임시 셀 편집 폴더와 분리하며 작업 종료 정리 대상에서 제외한다.

```text
generated/cell-edit-logs/<jobId>/
  original-composite.png
  original-cel.png
  request.json
  attempt-01-composite.png
  attempt-01-cel.png
  attempt-01-verdict.json
  ...
  attempt-06-composite.png
  attempt-06-cel.png
  attempt-06-verdict.json
  summary.json
```

시도별 두 PNG는 판정 에이전트에 전달한 후보 이미지와 동일하다. `request.json`은 사용자 요청, 대상 식별자와 모델 설정을 기록한다. `summary.json`은 최종 상태, 시도 횟수, 합격 시도 또는 최종 실패 이유와 각 파일의 상대 경로를 기록한다.

앱 상태 메시지는 현재 시도, 단계, 마지막 판정 요약과 로그 폴더의 프로젝트 기준 상대 경로를 표시한다. 로그는 성공, 품질 불합격, 기술 오류와 취소 모두에서 보존한다. 로그 폴더 경로는 반드시 해당 프로젝트 루트 내부로 검증한다.

## 종료와 오류 처리

- 합격: 합격 후보를 만든 동작 묶음과 시드를 반환하고 작업을 `completed`로 끝낸다.
- 품질 불합격: 남은 재편집이 있으면 다음 시도로 이동한다. 6번째 불합격이면 `failed`로 끝내고 원본을 유지한다.
- 사용자 취소: 현재 편집 또는 판정 실행을 중단하고 `cancelled`로 끝내며 원본을 유지한다.
- 편집·판정 실행 실패, 타임아웃, 잘못된 JSON 또는 금지된 도구 요청: 재편집 횟수를 소비하지 않고 기술 오류로 즉시 실패한다.
- 후보 동작 실행 실패: 부분 후보를 폐기하고 기술 오류로 끝낸다.
- 최종 클라이언트 적용 실패: 격리된 전체 결과를 폐기하고 문서, 실행 취소 이력과 편집기 설정을 요청 직전 상태로 유지한다.
- 취소와 완료가 경쟁하면 기존 셀 편집 작업의 먼저 확정된 상태를 유지하는 규칙을 따른다.

프로젝트 잠금은 작업의 모든 편집·판정 반복이 끝날 때까지 유지한다. 품질 불합격과 기술 오류는 사용자 메시지에서 명확히 구분한다.

## 사용자 경험

기존 작업 상태 영역을 재사용하며 별도 갤러리나 설정 화면은 추가하지 않는다. 실행 중에는 다음 정보를 표시한다.

- `현재 셀 편집 · 2/6 · 판정 중`
- 마지막 불합격 요약
- `로그: generated/cell-edit-logs/<jobId>`

합격하면 적용된 총 동작 수와 합격 시도를 표시한다. 최종 불합격이면 `6회 판정이 모두 불합격하여 원본 셀을 유지했습니다.`라고 표시한다. 취소와 기술 오류도 원본이 유지되었음을 알린다.

## 테스트

GUI와 실제 AI 호출 없이 결정적인 단위·서버 테스트를 우선한다.

1. 첫 후보 합격 시 한 번만 편집·판정하고 완료
2. 불합격 후 직전 후보·원본·최신 피드백으로 재편집하고 합격
3. 6회 모두 불합격하면 재편집 5회 후 실패하고 결과 미적용
4. 판정 합격 시 남은 횟수와 관계없이 즉시 종료
5. 편집과 판정이 서로 다른 새 스레드를 사용하고 판정 입력에 편집 문맥이 없는지 확인
6. 기술 오류가 품질 재편집 횟수를 소비하지 않고 즉시 실패하는지 확인
7. 취소와 최종 적용 오류에서 문서·이력·편집기 설정 보존
8. 같은 동작 묶음과 시드로 만든 서버 후보와 클라이언트 적용 결과의 픽셀 일치
9. 시도별 합성 PNG·셀 PNG·판정 JSON과 최종 요약 보존
10. 작업 상태의 단계, 시도 수, 판정 요약과 로그 경로 확인
11. 기존 현재 셀 편집, 이미지 생성과 선택 프레임 재생성 회귀 방지
12. `npm test`, `npm run build`, 코드 구현 후 `graphify update .`

## 완료 기준

- 현재 셀 편집이 최초 1회와 불합격 시 재편집 최대 5회를 수행한다.
- 편집과 판정이 동일 모델의 분리된 새 에이전트 스레드에서 실행된다.
- 판정 에이전트가 편집 과정이나 자기평가를 받지 않는다.
- 합격 결과만 적용되며 최종 불합격, 취소와 기술 오류에서는 원본이 유지된다.
- 판정에 사용한 모든 원본·후보 이미지와 구조화 판정이 작업별 로그에 보존된다.
- 판정한 후보와 실제 적용된 픽셀이 일치한다.
- 기존 편집 실행 취소와 프로젝트 잠금 규칙을 유지한다.
- 특정 편집 종류에 종속된 하드코딩 프롬프트를 추가하지 않는다.
